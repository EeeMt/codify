## 仪表盘 {core}

![五个页面各回答一个问题，按想知道的选一个](assets/diagrams/zh-CN/observability-map.svg)

按问题选页面：「仪表盘」看自己的工作，「统计分析」看趋势，「监控」看实时运行，「调度总览」看未来负载。

仪表盘是个人视图。六块摘要面板展示当前需求和任务状态，以及最近 90 天的变更行数、Token、任务活动和趋势。「我的工作看板」按状态分组，并可自动刷新；列被截断时会说明剩余数量并链接到完整列表。

「任务」页面是可访问记录的完整表格。顶部计数描述可见范围，不会随着表格筛选缩小。点击行可打开任务详情页。

## 统计分析

统计分析支持最近 7 天、30 天或 90 天，并可按项目和发起人筛选。它展示任务量、变更行数、执行时长、排队等待、状态分布、成功率和失败分类。

「概览」包含每日趋势，以及按项目和发起人的拆分；「模型服务」比较有 Provider 或模型归因的已结束任务。

看数字时注意三点：

- 发起人统计从引入发起人追踪后开始，项目统计包含历史任务。
- 平均 Token / 秒只使用输出 Token。
- 缺失的 Token 或变更数据不计入对应汇总。

仍在运行的任务不计入已结束任务的时长和成功率。统计分析可能只对管理员开放，也可能由管理员在系统配置中共享给平台用户。

## 监控

监控是运维视图，数据来自最新可见任务样本、全局任务统计和当前容器清单。

| 页签 | 主要问题 |
|---|---|
| **运行概览** | 当前有哪些任务在运行、可调度或等待？ |
| **容器排障** | 任务和 Docker 容器是否仍然对应？ |
| **健康信号** | 队列、容器、稳定性或运行时长是否出现压力？ |

活跃队列按优先级、到期状态、预约时间和创建顺序排列，等待前序任务会单独标出。容器关系包括「已关联」「任务缺失」「未映射」「容器晚于任务结束」「任务仍标记为运行中」和「历史」。Docker 目标不可达时会明确标记不可用，不会当成零容器。

健康结果分为「整体健康」「关注」和「需处理」，检查队列压力、Worker 对齐、过去 24 小时的失败或取消，以及运行超过 30 分钟的任务。监控通常是运维页面，也可以由系统配置共享。

## 调度总览

调度总览只展示带预约时间且仍为「待处理」「已入队」或「执行中」的活跃任务，用来查看计划负载。

| 视图 | 展示内容 |
|---|---|
| **未来 24 小时** | 按小时统计预约任务 |
| **繁忙与空闲窗口** | 即将到来的最忙和最空时段 |
| **7 天热力图** | 按小时显示负载；配置容量后显示数量 / 上限 |
| **选中时间窗口** | 某一小时内的任务和可编辑预约时间 |

页面还会显示当前到期、后续队列和满载时段。「只看我的」会改变统计范围。页面时间按当前显示的业务时区展示，本平台页面为 UTC+8。

启用登录时，只有管理员能在这里改期，而且只能编辑仍在待处理状态的预约任务。新时间必须在未来，并位于需求队列窗口内。

## 会话 {core}

「会话」管理的是控制台登录会话，不是 AI 对话。列表区分当前浏览器会话和已保存会话，并显示创建时间、最后访问、过期时间、刷新支持、令牌是否存在，以及可用时的 IP。

用「重新加载会话」刷新列表，用「撤销」立即让会话失效。撤销当前会话会退出登录。没有 refresh token 的会话，其访问 token 过期后可能需要重新进行 GitLab 登录。
