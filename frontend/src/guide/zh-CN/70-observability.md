## 仪表盘 {core}

![五个页面各回答一个问题，按想知道的选一个](assets/diagrams/zh-CN/observability-map.svg)

> [!tip] **按问题选页面**：想看自己的进度用仪表盘，想看趋势与成本用统计分析，想定位正在发生的故障用监控，想看未来负载用调度总览。

「仪表盘」（`/dashboard`）是打开控制台后的默认首页，定位是「在一个视图中跟踪排队任务、运行中的任务和已完成的合并请求任务」。

顶部统计卡给出四个数字：可见任务、执行中、待处理 / 已入队、已完成。下方是最近 90 天的趋势区：

| 图表 | 内容 |
|------|------|
| 需求状态 | 你的需求按打开、进行中、待审查、已关闭的分布 |
| 任务状态 | 你的任务按待处理、已入队、运行中、已完成、失败、已取消的分布 |
| 变更行数 | 任务产生的代码新增和删除总行数 |
| Token 用量 | 任务消耗的输入和输出 Token 总量 |
| 活动 | 每天完成的任务数量 |
| 趋势 | 完成任务数、代码变更量和 Token 消耗的每日趋势 |

「我的工作看板」按状态分列展示你关心的任务，每列有独立的空状态提示；条目过多时只显示前若干条，并提示「当前仅显示前 {shown} 条，共 {total} 条」，给出「查看更多」进入完整列表。右上角的「自动刷新」开关控制轮询，旁边显示「刚刚已更新」或「{n} 秒前更新」。

仪表盘只统计**你可见的任务**：认证用户看到的项目与任务会按 GitLab 权限过滤。访问根路径 `/` 会自动跳转到这里。

## 统计分析

「统计分析」（`/analytics`）面向近期窗口，需要 `analytics` 页面权限。时间范围可以选最近 7 天、最近 30 天或最近 90 天，并提供项目与发起人筛选。

「概览」页签包含：

- 任务量趋势、代码变更行数趋势、执行时长趋势
- 按项目、按发起人的成功率与时延表现
- 需求状态分布与任务状态分布（柱状或环形切换，支持「放大查看」）
- 按优先级的排队等待：任务开始执行前的平均与最坏等待时间
- 失败分类：按失败任务的错误信息归类，给出失败数、占比与示例

「模型服务」页签做 Provider 维度的对比，展示有服务归因的已结束任务量、成功率、Token 指标与效率指标：

| 指标 | 含义 |
|------|------|
| 活跃模型服务 | 窗口内有归因任务的模型服务数量 |
| 服务成功率 | 该模型服务已结束任务的成功比例 |
| 总 Token / 单任务平均 Token | 输入与输出的合计与均值 |
| 平均 Token / 秒 | 输出吞吐，仅基于输出 Token 统计 |
| 平均 Token / 变更行 | 生成一行代码变更的平均 Token 成本 |

口径说明：

- 发起人统计仅包含引入发起人追踪之后创建的任务，项目统计则包含历史任务。
- 「平均 Token / 秒」仅基于输出 Token 统计，与其它 Token 指标口径不同。
- 未知的 Token 或变更值不参与平均与总量计算。

如果当前筛选条件与时间窗口下没有数据，图表会显示对应的空状态。

## 监控

「监控」（`/monitor`）需要 `monitor` 页面权限。顶部是总览指标：活跃任务、24 小时完成、24 小时失败、长时间运行，以及「{count}/{max} 并发」。三个页签分别是：

- 「运行概览」：任务队列看板，列分为执行中、可调度、等待中与等待前序；可切换到「时间轴」与「表格」视图。卡片会显示并发占用（「{count}/{max} 并发」）、到期时间或「立即执行」。
- 「容器排障」：当前可见的工作容器清单，按时间倒序、运行中置顶，包含容器 ID、Docker 目标、状态、关联任务、存活时长与失败原因。无法关联任务的容器标记为「未映射」，晚于任务结束的容器标记为「容器晚于任务结束」。
- 「健康信号」：健康检查结论与明细，用「整体健康」「关注」「需处理」三档总结队列压力、容器对齐情况、近期稳定性与运行时长。

健康检查会专门列出两类异常：**缺少容器的运行中任务**（运行中任务看不到对应运行中容器）和**孤儿运行中容器**（运行中容器没有对应运行中任务）。「最近失败任务」区块直接暴露首行错误。如果某条需求需要修复回合序号，页面顶部会提示调度暂不可用。

页面数据来自「当前可见任务样本、全局任务统计，以及后端可见的工作容器汇总」，因此监控页反映的是全局实时状态，与任务列表的筛选无关。

## 调度总览

「调度总览」（`/schedule-overview`）需要 `schedule_overview` 页面权限。

- 「未来 24 小时」：按小时分桶的定时任务数量柱状图，支持「只看我的」、按状态筛选，以及按项目、分支或提示词搜索；点击任意非空小时柱即可查看该时段内的任务。
- 「繁忙与空闲窗口」：给出「最繁忙时段」与「空闲时段」，快速判断该把新任务预约到哪里。
- 「7 天热力图」：按小时着色，颜色越深表示计划负载越高；图例为「轻」「忙」「满」，悬浮显示 `{count}/{max}`。
- 「定时任务」：只包含活跃的定时任务，即待处理和执行中的任务，并按「当前到期」「未来 24 小时」「24 小时之后」分组。已到达执行时间的任务会标注「已经到达执行时间」。

点击时段后可以逐个调整任务时间。**只有管理员能在调度总览里改时间**：普通用户仍能查看该时段内的任务，但会看到「只有管理员可以在调度总览中调整任务时间」。这里只能修改仍处于待执行状态的预约任务，新的预约时间必须晚于当前时间。做这类调整前，值得先读一遍「调度」章节里的预约窗口约束。

## 会话 {core}

「会话」（`/sessions`）管理的是**控制台登录会话**，与任务的 AI 会话无关，不要混淆。

页面顶部显示已知会话数、活跃会话数与是否支持刷新，并说明令牌刷新的取舍：「如果某个会话没有 refresh token，即使控制台 Cookie 仍然存在，GitLab 访问令牌过期后也需要重新登录。」

会话列表区分「当前会话」与「已保存会话」，每条记录包含创建时间、最后访问、过期时间、刷新支持，以及是否已存储访问令牌与刷新令牌。当前浏览器正在使用的那一条会额外标记为「当前浏览器会话」。IP 不可用时会显示「IP 不可用」。

可用的操作包括：

- 「重新加载会话」：手动刷新列表。
- 「撤销」：让指定会话立即失效，成功后提示「会话已撤销」。

撤销当前会话会提示「当前会话已撤销，正在跳转到登录页」；撤销失败时页面会给出「撤销会话失败」的提示，可以重新加载后再试。会话记录会按保留期自动清理，不需要手工维护。
