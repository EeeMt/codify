## 前置条件

开始之前，确认下面几件事已经就绪：

- 一套已经部署并可访问的 Codify 实例。Compose 默认前端地址为 `http://localhost:8880`，后端 API 为 `http://localhost:8000`。
- 一个可访问的 GitLab 实例，以及机器人账号的 `GITLAB_URL` 与 `GITLAB_BOT_TOKEN`。
- 一个兼容 Harness 的模型服务端点：Claude 使用 Anthropic 协议，Codex 使用 OpenAI 协议。也可以在控制台的「系统配置」中打开「AI 模型服务」录入并在后续任务里选用。
- 一个可登录的账号：GitLab OIDC，或管理员创建的本地账号。

如果你还没有部署实例，可以在仓库的 `deploy` 目录一键启动：

```bash
cd deploy
docker-compose up -d --build
```

首次登录时，登录页会按当前认证模式展示入口：启用 OIDC 时显示「使用 GitLab 继续」，本地认证模式下显示「使用密码登录」。

## 三步循环

Codify 的主流程只有三步，所有页面都围绕它组织：

1. 写需求 — 在「需求」页创建 Issue，写清楚目标与约束。
2. 发起任务 — 在需求详情页点击「创建任务」，立即执行或预约到空闲时段。
3. 查看结果 — 跟踪状态、翻阅日志、检查交付物（提交、合并请求、运行归档）。

```mermaid
sequenceDiagram
    participant U as 用户
    participant C as 控制平面
    participant W as Worker 容器
    participant G as GitLab
    U->>C: 创建需求并发起任务
    C->>C: 冻结任务快照并加入队列
    C->>W: 启动隔离的 Worker 容器
    W->>G: 克隆仓库并推送工作分支
    W->>C: 上报事件流、日志与用量
    C->>G: 创建或更新 Merge Request
    C-->>U: 展示状态、日志与交付结果
```

任务结束后，需求详情页会给出「当前执行」与「执行记录」，任务详情页会给出日志、运行统计与交付信息。

### 第一次任务

从空仪表盘到一次可评审的变更，最短路径是：

1. 打开「需求」并选择「创建需求」。填写「项目」「起始分支」「合并目标」，在「描述」里写清你想要的结果。
2. 在新建的需求上选择「创建任务」。「任务模式」保持默认的「实施模式」，优先级没有特别理由也不必改。
3. 「立即执行」保持选中后提交。需求会显示为「进行中」，并在「当前执行」中出现一次运行。
4. 打开这次任务。运行期间观察「事件流」与「原始日志」两个标签页，事件流会自行刷新。
5. 状态变为「已完成」后，查看「提交记录」与交付结果，以及「运行统计」中的代码变更与 Token 数字。

如果任务以「失败」结束，任务的「错误」区块会在重试之前给出失败原因与类型。「重试」复用同一份冻结配置，因此只有原因是提示词、配置或环境时才需要改动——瞬态故障不必改。

要在同一个需求上做更多事，用「追加任务」而不是从头新建任务：追加的任务共享同一 workspace、AI 会话和 Git 分支，可以接着上一次停下的位置继续。

## 界面导航

侧边栏按「工作区」「分析与运维」「管理」三组组织页面，其中分析与运维页面需要按角色分配的页面权限。

| 页面 | 路由 | 用途 |
|------|------|------|
| 仪表盘 | `/dashboard` | 任务概览、最近 90 天趋势与「我的工作看板」 |
| 需求 | `/issues` | 需求列表与详情，任务都从这里发起 |
| 创建需求 | `/issues/create` | 用提示词模板快速描述需求 |
| 任务 | `/tasks` | 任务列表，按项目、状态、优先级、Harness 筛选 |
| 会话 | `/sessions` | 查看并撤销控制台登录会话 |
| 统计分析 | `/analytics` | 工作量、成功率、排队等待与模型服务对比 |
| 调度总览 | `/schedule-overview` | 未来 24 小时排程密度与 7 天热力图 |
| 监控 | `/monitor` | 队列看板、执行时间线与健康检查 |
| 系统配置 | `/configuration` | 管理员维护运行时、Provider、Worker 等配置 |
| 访问管理 | `/access-management` | 管理员管理用户、角色与状态 |

注意 `/create-task` 是旧路径，会重定向到 `/issues/create`；在需求详情页发起的任务才是日常入口。
