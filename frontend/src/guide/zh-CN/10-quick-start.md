## 先看懂需求和任务

需求是一条持续推进的工作线，任务是其中的一次执行。需求持有工作区、会话记录和工作分支 `codify/issue-{id}`；同一需求里的任务按顺序运行，并把提交送到同一条分支；开启合并请求时，再汇入同一个 Merge Request。

结果还需要调整时，在原需求上追加任务。项目、起始分支、合并目标或 Worker 需要改变时，再创建新需求。

![需求只创建一次，回合可以反复追加](assets/diagrams/zh-CN/issue-loop.svg)

## 完成第一次任务

开始前需要一个可登录的账号、一个可访问的 GitLab 项目，以及一个已经启用 Harness 的 Worker。如果创建表单里没有项目或 Worker，请让管理员检查[系统配置](/guide/80-admin-configuration)和 GitLab 机器人账号的项目权限。

从空白仪表盘到第一份可评审结果，只需完成下面几步：

1. 打开[创建需求](/issues/create)，选择项目、起始分支、合并目标和 Worker。标题写清要解决的问题，描述里放跨回合的背景；本回合目标、范围和验收标准写在任务的「提示词」里。
2. 提交后，在需求详情页点击「创建任务」。需要修改并提交代码时选择「实施模式」，优先级保持默认的 P1 即可。
3. 保持「立即执行」并提交。任务会先进入队列，获得并发容量后开始运行。
4. 打开任务详情页。运行期间看「事件流」了解当前动作；需要排查容器输出时再切到「原始日志」。
5. 状态变为「已完成」后，检查提交记录、交付结果和运行统计，再打开 Merge Request 评审代码。

创建需求的字段和冻结规则见[《创建需求》](/guide/15-create-issue)，任务模式与调度选项见[《创建任务》](/guide/30-create-task)。

## 完成后怎么做

| 当前情况 | 下一步 |
|---|---|
| 结果符合预期 | 评审并合并 Merge Request，需求会随之关闭 |
| 还要修改或补测试 | 在同一需求上「追加任务」，继续使用当前工作区、会话和分支 |
| 任务因瞬态故障失败 | 重试失败任务；重试会沿用原任务冻结的配置 |
| 提示词、配置或运行环境需要改变 | 修正原因后再重试，或者追加一条说明更准确的任务 |
| 项目、分支策略或 Worker 需要改变 | 创建新需求，这些设置在需求创建后不能修改 |
| 任务长时间没有运行 | 先看任务的队列提示，再查[《运行与引导》](/guide/40-run-and-steer)和[《调度》](/guide/60-scheduling) |

同一需求里的后续任务会接着已有代码继续。需要换 Harness，或旧对话已经妨碍下一步判断时，可以在追加任务时选择「使用新会话执行」；工作区和分支仍会保留。
