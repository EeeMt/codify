## 前置条件

开始之前，确认下面几件事已经就绪：

- 一个可登录的账号：通过 GitLab 登录时首次登录会自动建档，角色默认是 `platform_user`，用户名或 GitLab 组命中服务端配置的管理员规则时是 `platform_admin`；管理员可以在「访问管理」里改角色或停用账号。带本地密码的只有初始化时创建的那个管理员账号。
- 一个你能够访问的 GitLab 项目，需求与工作分支都落在它上面。项目还必须对 **GitLab 机器人账号** 可见：Codify 用这个机器人账号列出项目、克隆仓库、推送工作分支并创建合并请求，因此它需要是项目的成员，并具备 **推送分支与创建合并请求** 的权限（GitLab 的 Developer 角色即可满足这两项；Guest 与 Reporter 不能推送代码）。缺少推送权限则任务会在推送工作分支这一步失败。
- 一个启用了可用 Harness 的 Worker，创建任务时能选中它。Harness 按 Worker 配置启用，可选值为 Claude、Codex、Pi 或 OpenCode。

登录页在 `/login`，能看到的入口由平台的认证模式决定：启用 OIDC 时默认显示「使用 GitLab 继续」，展开切换按钮可以改用「使用密码登录」；未启用 OIDC 时只剩密码入口。管理员若启用了紧急入口，页面下方还会出现「紧急访问」区块，用环境变量里配置的账号登录，供 OIDC 故障或管理员被锁定时使用。系统尚未初始化时，所有路由都会跳到初始化页，先创建首个管理员账号。

「创建需求」的项目列表按登录方式取自不同的令牌：管理员看到的是机器人账号能列出的项目，通过 GitLab 登录的普通用户看到的是自己账号能访问的项目，两者不取交集，所以列表里有项目并不代表机器人账号能克隆或推送它。平台本身由管理员维护：Worker 与模型服务在「系统配置」里配置，账号角色与状态在「访问管理」里维护；相关章节见《管理指南》。

> [!tip] **最快路径**：创建需求 → 创建第一个任务 → 观察事件流 → 评审提交 → 在同一需求上追加或关闭。先把这条主线跑通，再阅读管理章节。

## 一个需求，多个回合

Codify 的日常工作围绕同一个需求反复推进：需求只创建一次，工作区、AI 会话与工作分支都归它所有；之后每一轮都是在它上面追加一个任务，也就是一个回合。

- **创建需求**：在「需求」页写清目标与约束。工作区、会话与分支从这里开始就归属这个需求，后面不再重建。
- **创建 / 追加任务**：需求上还没有任务时，按钮是「创建任务」；之后是「追加任务」。追加的回合共享同一份上下文，接着上一个回合停下的位置继续。
- 运行与评审：回合在隔离容器中执行，状态、事件流与日志实时回传。「当前执行」与「执行记录」会列出这个需求的每个回合，任务详情页给出日志、运行统计与交付物；必要时可以在中途引导它。
- 收尾：结果满意时，合并这个需求唯一的合并请求，需求随之关闭；不满意就继续追加下一个回合。

### 第一次任务

从空仪表盘到一次可评审的变更，最短路径是：

1. 打开「需求」并选择「创建需求」，按《创建需求》章节填表：选定「项目」，写清「标题」与「描述」，确认「起始分支」与「合并目标」，再挑一个 Worker。
2. 在新建的需求上选择「创建任务」，在「选择任务模式」这一步挑一个模式：要改代码并提交就选「实施模式」。优先级没有特别理由不必改。
3. 「立即执行」保持选中后提交。需求会显示为「进行中」，并在「当前执行」中出现一次运行。
4. 打开这次任务。运行期间观察「事件流」与「原始日志」两个标签页，事件流会自行刷新。
5. 状态变为「已完成」后，查看「提交记录」与交付结果（改动行数就在提交记录里），以及「运行统计」中的 Token 数字。

如果任务以「失败」结束，任务的「错误」区块会在重试之前给出失败原因与类型。「重试」复用同一份冻结配置，因此只有原因是提示词、配置或环境时才需要改动；瞬态故障不必改。

一个回合结束后，需求本身还在。接下来通常是在同一个需求上选「追加任务」，而不是回到「需求」列表新建一个需求：追加的回合共享同一工作区、AI 会话与 Git 分支，会接着上一个回合停下的位置继续，最终仍然只有这一个需求的一个合并请求。

## 界面导航

侧边栏按「工作区」「分析与运维」「管理」三组组织页面，其中分析与运维页面需要按角色分配的页面权限。

| 页面 | 路由 | 用途 |
|------|------|------|
| 仪表盘 | `/dashboard` | 任务概览、最近 90 天趋势与「我的工作看板」 |
| 需求 | `/issues` | 需求列表与详情，任务都从这里发起 |
| 任务 | `/tasks` | 任务列表，按项目、状态、优先级、Harness 筛选 |
| 会话 | `/sessions` | 查看并撤销控制台登录会话 |
| 统计分析 | `/analytics` | 工作量、成功率、排队等待与模型服务对比 |
| 调度总览 | `/schedule-overview` | 未来 24 小时排程密度与 7 天热力图 |
| 监控 | `/monitor` | 运行概览、容器排障与健康信号 |
| 系统配置 | `/configuration` | 管理员维护运行时、Provider、Worker 等配置 |
| 访问管理 | `/access-management` | 管理员管理用户、角色与状态 |

顶栏还有两个快捷入口：加号按钮的提示是「创建新需求」，打开 `/issues/create`；书本按钮的提示是「查看指南」，打开 `/guide`。

注意 `/create-task` 是旧路径，会重定向到 `/issues/create`；在需求详情页发起的任务才是日常入口。
