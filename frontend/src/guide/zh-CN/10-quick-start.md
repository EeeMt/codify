## 先看懂需求和任务

需求是一条持续推进的工作线，任务是其中的一次执行。需求持有工作区、会话记录和工作分支 `codify/issue-{id}`；同一需求里的任务按顺序运行，共用这条分支，开启合并请求时也共用同一个 Merge Request。

还要改一轮，就在原需求上追加任务。项目、起始分支、合并目标或 Worker 要变，再创建新需求。

![需求只创建一次，回合可以反复追加](assets/diagrams/zh-CN/issue-loop.svg)

## 完成第一次任务

开始前需要登录账号、可访问的 GitLab 项目，以及启用了 Harness 的 Worker。如果表单里没有项目或 Worker，请让管理员检查[系统配置](/guide/80-admin-configuration)和机器人账号的 GitLab 权限。

从空白仪表盘到第一份可评审结果，只需完成下面几步：

1. 打开[创建需求](/issues/create)，选择项目、起始分支、合并目标和 Worker。描述里放跨回合仍成立的背景；本回合目标、范围和验收标准写在任务「提示词」里。
2. 提交后点击「创建任务」。需要改代码并提交时选择「实施模式」，普通工作保持 P1 即可。
3. 保持「立即执行」并提交。任务进入队列，有并发容量后开始。
4. 运行期间看「事件流」；需要查容器输出时再看「原始日志」。
5. 状态变为「已完成」后，检查提交记录、交付结果和运行统计，再打开 Merge Request 评审代码。

创建需求的字段和冻结规则见[《创建需求》](/guide/15-create-issue)，任务模式与调度选项见[《创建任务》](/guide/30-create-task)。

## 完成后怎么做

| 当前情况 | 下一步 |
|---|---|
| 结果符合预期 | 评审并合并 Merge Request，需求会随之关闭 |
| 还要修改或补测试 | 在同一需求上「追加任务」 |
| 任务因瞬态故障失败 | 重试；重试沿用源任务冻结的配置 |
| 提示词或运行环境有问题 | 修正原因后重试，或追加一条说明更准确的任务 |
| 项目、分支策略或 Worker 要改变 | 创建新需求；这些设置创建后不能改 |
| 任务长时间没有运行 | 先看任务的队列提示，再查[《运行与引导》](/guide/40-run-and-steer)和[《调度》](/guide/60-scheduling) |

同一需求里的后续任务会接着已有代码继续。要换 Harness，或旧对话已经妨碍判断时，追加任务可选择「使用新会话执行」；工作区和分支仍会保留。
