## 任务生命周期

任务有六个状态，界面上的标签与含义如下：

| 状态 | 标签 | 含义 |
|------|------|------|
| `PENDING` | 待处理 | 已创建，等待调度；到达预约时间或手动立即执行后进入队列 |
| `QUEUED` | 已入队 | 已满足执行条件，等待并发容量释放后自动开始 |
| `RUNNING` | 执行中 | Worker 容器正在执行 |
| `COMPLETED` | 已完成 | 执行成功，交付产物已生成 |
| `FAILED` | 失败 | 执行失败，含超时、协议错误、认证失败、限流、沙箱失败与 Harness 错误 |
| `CANCELLED` | 已取消 | 被用户取消 |

![六个状态，以及哪些状态下你能操作](assets/diagrams/zh-CN/task-lifecycle.svg)

任务进入已入队状态时，所属需求的状态会同步变为「进行中」。终态（已完成 / 失败 / 已取消）不会再回到运行态。

任务详情页顶部会按状态给出「执行结论」：待处理时说明「任务已创建，达到预约时间或手动立即执行后将进入调度队列」；已入队时说明「任务已满足执行条件，系统会在并发容量可用后自动开始」；失败时建议先看失败原因和事件流，再决定立即重试或预约重试。

## 实时进程日志

![先观察运行，再根据结果选择引导、追加、重试或归档](assets/diagrams/zh-CN/run-and-steer.svg)

「日志」面板在任务执行中展示容器输出，任务结束后展示已存储日志；执行中的面板带有「实时」标记。视图有两个页签：

- 「事件流」：结构化展示 Harness 的思考、工具调用、子代理与交付摘要。工具调用会显示次数（「{count} 次工具调用」）和输入 / 输出内容；思考与子代理有独立的标记与耗时。
- 「原始日志」：容器 `console.log` 的原样输出，支持 ANSI 颜色渲染与 emoji。日志过大时只渲染最近的片段，并提示可以从运行归档下载完整日志。

面板在任务执行中会自动刷新。若任务已经开始执行，「任务概览」会显示本次的「本次超时上限」与「执行截止时间」；未开始时分别显示「开始执行时确定」与「本次执行未记录」。

执行失败时，「失败原因」区块会给出最近一次上报的错误信息、失败类型与原始输出（可展开「显示完整输出」）。日志会经过敏感信息脱敏后再存储。

运行结束后，「运行统计」卡片给出 Token 消耗，以及「上下文压缩」与「Skill 使用」的次数（按 Skill 细分）。

> [!info] **先看状态再操作**：「事件流」适合跟踪任务做了什么，「原始日志」适合定位容器问题。

## 引导运行中的任务

如果当前 Harness 支持控制通道，任务详情页会出现「实时引导」面板。目前只有 Pi 支持控制通道，其余 Harness 不会出现该面板，控制门保持禁用。面板提供两种命令：

- 「转向」（`steer`）：向运行中的 Harness 发送补充指令，影响它接下来的动作。
- 「续接指令」（`follow_up`）：在当前回合收尾后追加一轮新的指令。

面板右上角的门状态说明当前能否发命令：

| 门状态 | 含义 |
|--------|------|
| 启动中 | 等待 Harness 控制端点就绪 |
| 可接收命令 | 可以发送 |
| 排空中 | 任务正在收尾，不再接收新命令 |
| 已关闭 | 控制通道关闭 |

只有在任务执行中且门状态为「可接收命令」时输入框才可用；任务结束后面板保留，用于回看历史命令。每条命令都会显示类型、序号、内容和状态：已排队、发送中、Harness 已接收、已拒绝、结果未知。

「Harness 已接收」只表示接口确认收到，不保证模型已消费该消息；确认通常发生在下一个回合边界，可能需要等待一段时间。状态为「结果未知」的命令不会被重放。

## 追加后续任务

在需求详情页点击「追加任务」即可发起下一个回合。追加任务会共享同一工作区、AI 会话与 Git 分支，因此可以在上一次任务的基础上继续推进。这是迭代式工作的主要方式，不必反复创建新需求。下一个回合从工作分支继续，包括你自己推送到远端的提交；分支的创建与推送规则见《交付》。

追加时可以选择：

- 提示词：本次要接着做什么。
- 会话策略：续接当前会话，或勾选「使用新会话执行」开启新一代会话。
- Harness：续跑沿用当前 Harness；要切换必须开新会话。
- 优先级与调度方式：与首个任务相同。

新任务会拿到下一个回合序号。前一个任务未结束时，新任务会显示「排队第 {position} 位 · 等待 Task #{blockedBy}」，等前序任务释放需求锁后自动开始。任务详情页在任务是最新回合时会显示「追加任务继续」，在仍有后续回合时会引导你回到需求详情页继续操作。

### 什么时候开启新会话 {tips}

需求上的对话开始帮倒忙时就值得勾选「使用新会话执行」：某个回合跑偏、折腾很久也没找到正确方向，下一个回合要换到代码库的另一部分，或者要更换 Harness（续跑会话不允许切换）。工作区与分支都会保留，重开对话不会丢代码。

## 取消、重试与强制收尾

**取消**：待处理、已入队、执行中的任务都会显示「取消」按钮。操作会停止执行并保留最新状态与日志，便于后续排查。正在运行的任务会先收到取消请求，由执行链路收敛到已取消状态；容器会被优雅停止，必要时强制结束。

**重试**：失败或已取消的任务会显示「重试」。重试会沿用源任务冻结的 Harness 快照与模型服务快照，用相同的提示词与分支配置生成一个新任务重新入队，发起人则是执行重试的人；源任务的记录在需求详情页以「已重试 →」指向新任务，新任务则在「重试自」一行标出源任务。同一个源任务只能有一个进行中的重试；已存在时会提示「该任务已有重试任务」。

如果不想立即重试，可以用「预约重试」选择一个未来时间。若源任务属于更旧的会话线代，界面会要求「使用源配置开启新会话重试」，此时重试会开启全新会话。

**执行控制**：待处理任务可以用「立即执行」移除调度延迟；有预约时间的待处理任务，以及已入队的任务，可以用「修改预约」改期。非队首的任务即使立即执行，也要等前序任务完成，界面会明确提示队列位置与被阻塞对象。

**手动修正**：已完成的任务提供「标记为失败」，失败的任务提供「标记为成功」，用于修正系统判定。操作前会提示这将影响数据统计和需求状态；可以填写「修正原因（选填）」，该原因随任务记录一起保存。

只有管理员或任务发起人才能操作任务；其他用户可以查看详情，但不能执行这些操作。任务详情页的「操作」区只展示当前状态下可用的按钮，没有可用操作时会显示「当前任务状态下没有可用的手动操作」。
