## 任务生命周期

任务会经过六个状态。任务详情页上的状态和队列提示，就是判断下一步的依据。

![六个状态，以及哪些状态下你能操作](assets/diagrams/zh-CN/task-lifecycle.svg)

| 状态 | 含义 |
|---|---|
| **待处理** | 已创建，等待预约时间或「立即执行」 |
| **已入队** | 已满足条件，等待 Worker 容量或同一需求的前序任务 |
| **执行中** | Worker 正在运行，事件流会持续更新 |
| **已完成** | 运行成功结束，可查看结果、提交和交付信息 |
| **失败** | 运行以错误结束，先看错误卡片再决定是否重试 |
| **已取消** | 运行被停止，事件和日志仍然保留 |

队列提示会说明具体原因。非队首任务可能显示「排队第 {position} 位 · 等待 Task #{blockedBy}」；队首任务可能在等预约时间或 Worker。运行时未验证时，任务会保持「待处理」，并显示「无法调度：Worker Runtime 不可用」，直到管理员修复并重新验证。

只有任务发起人或管理员可以操作任务，其他用户仍可查看详情。

## 实时进程日志

![先观察运行，再根据结果选择引导、追加、重试或归档](assets/diagrams/zh-CN/run-and-steer.svg)

用「事件流」跟踪运行，用「原始日志」定位容器问题。

| 视图 | 适合查看 |
|---|---|
| **事件流** | 助手文本、思考、工具调用及其输入输出、上下文压缩、子代理和交付事件 |
| **原始日志** | 容器输出，尤其是启动和运行时错误 |

没有相应数据时，面板会显示「任务尚未开始」「暂无事件」或「暂无日志」。面板还会记录思考和子代理状态、工具输入输出、上下文压缩与 Skill 使用次数。浏览器会截断过大的输出，任务结束后下载运行归档可取得完整日志。

## 引导运行中的任务

冻结的 Harness 声明支持控制通道时，任务页才会显示「实时引导」。当前只有 Pi 暴露该能力，其他 Harness 的控件不可用。

| 命令 | 用途 |
|---|---|
| **转向** | 运行中发送补充指令，影响后续动作 |
| **续接指令** | 当前回合结束后排入下一轮指令 |

命令状态包括「已排队」「发送中」「Harness 已接收」「已拒绝」和「结果未知」。控制门状态包括「启动中」「可接收命令」「排空中」和「已关闭」。「Harness 已接收」只说明接口收到命令，不代表模型已经执行；请回到事件流确认效果。

## 追加后续任务

下一轮还属于同一需求时，使用「追加任务」。保持「继续会话」会复用需求的工作区、分支和会话，并把新任务放到该需求队列末尾；新任务的提示词和运行指令仍需单独填写。

旧对话已经无助于判断，或要换 Harness 时，选择「使用新会话执行」。工作区、分支和旧会话记录仍会保留；续接会话的任务必须沿用当前 Harness。

CI 自动创建的后续任务会标记为「CI 自动修复」，手动追加和重试也会在任务元数据里标明各自来源。

### 什么时候开启新会话 {tips}

出现错误诊断、长时间跑偏、问题转向代码库另一部分，或要更换 Harness 时，适合开启新会话。代码会保留，对话从头开始。

## 取消、重试与强制收尾

「操作」区只展示当前状态允许的动作。

- **取消**适用于「待处理」「已入队」和「执行中」。它会移除排队任务，或请求运行中的容器停止，并保留任务记录和日志。
- **重试**适用于「失败」和「已取消」。它会用源任务的提示词、分支设置、冻结快照和会话线代创建新任务，源任务本身不变。「预约重试」可以把新任务安排到未来时间。
- **立即执行**适用于「待处理」任务，移除自己的预约等待，但仍不能跳过同一需求的前序任务。
- **修改预约**可以调整仍在待处理或已入队任务的时间，新时间必须在未来且位于该需求的队列窗口内。
- **标记为失败**和**标记为成功**用于修正终态。可填写修正原因并留存审计记录，代码、日志和交付物不会改变。

如果重试源属于比当前队列末尾更旧的会话线代，系统会询问是否新开一代会话；已有进行中的重试时，页面会提示「该任务已有重试任务」。

失败任务先看「失败原因」和失败类型；摘要不够时用「显示完整输出」展开原始错误。
