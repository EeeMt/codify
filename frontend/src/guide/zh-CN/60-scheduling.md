## 队列与优先级仲裁 {core}

任务创建后先是「待处理」，满足条件后进入「已入队」，被 Worker 领取后才是「执行中」。调度器按配置的间隔检查工作，每轮提升符合条件的需求队首，最多启动一个任务。

![开始执行前要过三道闸：回合顺序、预约时间、并发容量](assets/diagrams/zh-CN/why-a-task-waits.svg)

同一需求的回合顺序是第一道闸。不是需求队首的任务不能被提升，无论优先级多高。符合条件的队首按以下顺序选择：

1. 优先级：P0、P1、P2。
2. 已到预约时间的任务优先于立即执行任务。
3. 预约时间更早的优先。
4. 创建时间更早的优先，最后按任务 ID 区分。

> [!warning] 排队不一定是故障。先看队列提示，区分是在等前序任务、预约时间，还是并发容量。

任务从「已入队」变成「执行中」时会再次检查回合序号，避免旧的队列视图启动错误回合。

## 并发与同需求互斥

「最大并发数」是平台同时允许运行的任务数。所有槽位被占用时，符合条件的任务会保持「已入队」。

每条需求还有一把互斥锁。同一需求同时只能运行一个任务，任务进入终态且容器退出后才释放锁。这样可以保护跨回合共用的工作区和 Harness 会话。

需要并行推进时拆成多个需求；同一需求里的任务始终按回合顺序运行。

## 预约窗口与时段容量

预约有两层互不相同的限制：

- **需求队列窗口**：同一需求内，新任务或改期任务不能早于前序活跃任务的预约时间，也不能晚于后续活跃任务的预约时间。表单会显示上下界，没有可用时间时直接拒绝。
- **时段容量**：「每小时时段最大任务数」限制一个小时内的活跃预约任务数，0 表示不限制。「强制执行时段限制」开启后满载会拒绝创建，关闭时只警告。

创建预览和「调度总览」只统计仍为「待处理」「已入队」或「执行中」且带预约时间的任务。时段容量用于分散计划负载，不会限制已经运行的任务。改期仍要求新时间在未来且位于需求队列窗口内。

## 超时策略 {core}

管理员分别设置高峰和低峰上限：

| 配置 | 含义 |
|---|---|
| **高峰开始 / 结束** | 业务时区中的 24 小时制 HH:mm 窗口 |
| **高峰超时** | 在窗口内开始的任务使用的上限 |
| **低峰超时** | 在窗口外开始的任务使用的上限 |

任务进入「执行中」时只选择一次档位和上限，跨过时间边界也不会改变本次运行。任务详情页在有记录时显示「本次超时上限」和「执行截止时间」。超过上限以「失败」结束，类型为「超时」；用户取消则是「已取消」。

支持范围和安装默认值见[《平台参考》](/guide/96-platform-reference)。

## 中断与恢复

平台或 Worker 中断时，恢复流程会对照任务记录和容器状态：

| 情况 | 恢复结果 |
|---|---|
| 运行中的容器仍在 | 重新接管，继续收集事件和日志 |
| 容器已退出但任务仍在运行 | 收齐结果后结束任务 |
| 运行中任务找不到容器 | 标记为「失败」；收到过取消请求时标记为「已取消」 |
| 容器没有对应的运行中任务 | 按孤儿容器清理 |
| Docker 目标暂时不可达 | 保留任务归属，后台继续重试 |

恢复不会重排任务或重置回合序号。前序运行仍在收尾或清理工作区时，后续任务会继续等待；回合序号需要修复时，该需求的调度会暂停，直到管理员处理。
