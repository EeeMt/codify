## 访问管理与角色

「访问管理」（/access-management）列出控制台用户、角色、状态、活跃会话和最近登录时间。

### 角色来源与状态

用户只有一个角色：「平台管理员」或「平台用户」；状态为「启用」或「已禁用」。

| 角色来源 | 含义 |
|---|---|
| **Bootstrap** | 由配置中的管理员用户名或组授予 |
| **手动覆盖** | 在访问管理中明确设置，优先于 Bootstrap |
| **紧急入口** | 由部署环境控制的紧急管理员 |

禁用用户会撤销其活跃会话。最后一个活跃平台管理员不能被降级或禁用。

### 修改访问权限

用筛选或搜索找到用户，修改角色或状态后选择「保存访问权限」。「撤销会话」会立即使该用户的所有活跃会话失效。自己的角色和状态在自己的行中只读；要修改请使用另一位管理员的会话。

## 用量管理

![配额在创建时和执行前各拦一次，四项配额都计数](assets/diagrams/zh-CN/quota-gates.svg)

「用量管理」显示系统默认值和用户覆盖值。任务创建时检查一次，开始运行前再检查一次，因此任务可能已经创建，却在配额满载时无法开始。

### 限制模型

| 维度 | 窗口 |
|---|---|
| 每日 Token | 当前业务日 |
| 每周 Token | 从周一开始的业务周 |
| 每日任务 | 当前业务日 |
| 每周任务 | 从周一开始的业务周 |

用量在任务结束时记账。系统默认支持「自定义」和「不限制」，用户覆盖还可以「继承」系统值；自定义上限必须为正数。

### 拦截点

结构化原因是 usage_limit_exceeded，其中会列出超出的维度、当前用量、上限和重置时间。比较使用严格大于：用量正好等于上限时仍可继续，下一条使其超过上限的任务会被拦截。

### 阅读页面

「系统默认值」是平台基线，「用户覆盖」显示每个用户的改动和超限用户。修改后保存对应卡片即可。

## 系统统计

「系统统计」（/system-statistics）用于查看系统生命周期，不是计费或审计依据。它把保留数据与标准删除流程产生的快照合并展示，并标出统计时区。

### 当前运行状态与累计总量

「当前运行状态」实时显示待处理、已入队、执行中、长时间运行、活跃需求和平均排队等待。「生命周期累计」汇总任务与需求数量、结果、MR、已知 Token、代码变更、执行时间和删除计数。

### 覆盖率、趋势与拆分

「数据覆盖率」说明已结束任务中 Token 和代码变更数据的完整、部分和缺失情况；未知值不进入平均值和总量。「基础趋势」按天统计创建、结束、删除的任务及新建需求；「基础拆分」按项目、Provider、Harness 和任务模式分组。

### 保留数据与已删除数据

用「趋势时间范围」和「数据状态」选择全部、保留或已删除数据。已删除记录只显示脱敏快照，没有详情链接。删除覆盖保证未启用时，页面不会把已删除数据计入统计，并会明确提示。

## 数据清理

「系统数据清理」删除超过期限的需求及其任务数据。

- 「清理早于 N 天的数据」按需求年龄判断，不看单个任务年龄；N 至少为 1。
- 不开启强制模式时，仍有活跃任务的需求会跳过。
- 「强制清理活跃任务」会处理待处理、已入队和执行中的任务，并尝试停止容器；容器无法停止时跳过整个需求。
- 被删除的工作区和运行归档会尽力清理。缺失的归档文件会记录在结果里，不会让整批操作中断。

操作不可撤销，执行前会要求确认。结果会报告删除的需求和任务、跳过的活跃需求以及清理错误；按结果修复原因后再重试。

## 维护

「维护操作」提供：

- 「重新加载」：重新读取当前生效配置。
- 「重置为环境变量/默认值」：确认后删除所有持久化覆盖，包括已保存的密钥覆盖；之后使用环境变量或内置默认值，不删除任务和用户记录。

Worker 工作区宿主机路径、加密根密钥、Worker Kit 安装和数据库结构属于部署约束。加密密钥必须保持稳定；更换 Kit 或镜像后要重新验证 Worker Profile。
