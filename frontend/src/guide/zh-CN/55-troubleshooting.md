## 先判断问题在哪

先看任务状态和页面提示。「事件流」用于看结构化运行过程，「原始日志」用于看容器输出；涉及 Worker、Docker、OIDC 或系统故障时，转到[《平台排障》](/guide/90-troubleshooting)。

![先按症状分流：用户可以自助处理的任务问题，或需要管理员介入的平台问题](assets/diagrams/zh-CN/troubleshooting-split.svg)

| 现象 | 先检查 |
|---|---|
| 任务「失败」 | 「错误」卡片和失败类型 |
| 任务「待处理」或「已入队」 | 预约时间、前序任务、容量和队列提示 |
| 提示词缺失或方向不对 | 任务提示词和运行指令模板，尤其是 {{user_prompt}} |
| 登录、403 或项目缺失 | 下面的登录与权限表 |
| 容器缺失或运行时不可用 | [《平台排障》](/guide/90-troubleshooting) |

## 任务失败时先看什么

先读「错误」卡片，再按「事件流 → 原始日志 → 运行归档」收集证据。

| 错误特征 | 通常原因 | 下一步 |
|---|---|---|
| Task timed out after &lt;n&gt;s | 任务用完了开始执行时冻结的超时上限 | 拆小工作，或让管理员调整后续任务的超时策略 |
| usage_limit_exceeded | 创建或执行时触发任务数或 Token 配额 | 查看超出范围和重置时间，向管理员询问「用量管理」 |
| Code delivery was not confirmed... | 推送被拒绝或结果无法确认 | 把项目、分支和错误交给项目负责人或管理员 |
| protocol_error: ... | Harness 事件和进程状态不一致 | 先重试一次，重复出现时保留运行归档 |
| worker_runtime_unavailable / harness_cli_unavailable | 冻结的 Worker 或 Harness 当前不可用 | 不要反复重试，让管理员恢复并重新验证 |
| Worker failed to start: ... | 容器没有成功启动 | 把任务编号和错误卡片交给管理员 |
| Cancelled by user | 任务被主动取消 | 仍需继续时追加任务或再次运行 |

容器在产生第一行输出前就失败时，原始日志为空是正常的，错误卡片仍是主要依据。归档过期后不能再下载。

## 任务没有开始

「待处理」和「已入队」都不代表失败。

| 队列提示 | 含义 |
|---|---|
| 预约时间在未来 | 等待，或使用「立即执行」 |
| 等待前序任务 | 同一需求一次只运行一个任务 |
| 等待 Worker | 其他需求占用了全部并发槽位 |
| Worker Runtime 不可用 | 平台条件异常，需要管理员处理 |
| 所有任务都在等待 | 让管理员检查调度器、Worker 和系统健康 |

预约时间只决定任务何时有资格进入队列，不能跳过同一需求的回合顺序。任务仍为「待处理」或「已入队」时，可以用可用的编辑操作调整预约、优先级或内容；开始运行后，这些修改不会改变当前执行。

## 登录、项目和交付权限

| 症状 | 先检查 | 仍不行时 |
|---|---|---|
| 登录循环 | 会话是否过期、站点 Cookie 是否保存 | 重新登录；仍反复发生时让管理员检查 OIDC |
| Admin access required | 页面是否仅管理员可用 | 请求合适角色或共享页面权限 |
| 找不到项目 | 当前账号的项目权限，以及机器人账号是否能看到项目 | 让管理员确认权限并刷新项目缓存 |
| 任务不能推送或创建 MR | 机器人推送/MR 权限和受保护分支规则 | 把错误和项目路径交给负责人或管理员 |
| 共享页面被拦截 | Monitor、Schedule Overview 或 Analytics 是否已开放 | 让管理员在「系统配置」中开启 |

能登录 Codify、能看到项目，都不代表机器人可以向项目推送代码。不要把令牌写入任务提示词或日志。

## 可以怎么处理

| 需要 | 操作 |
|---|---|
| 用同一份冻结配置再次运行 | 「重试」 |
| 在现有代码上继续 | 「追加任务」 |
| 保留代码但清掉旧对话 | 追加时选择「使用新会话执行」 |
| 更换项目、分支、合并目标或 Worker | 新建需求 |

每条追加任务仍要写自己的目标、范围和验证方式。跨回合背景放在需求描述里，本次工作放在任务提示词里。

## 常见问题

### 为什么任务失败但没有原始日志？

任务可能在容器启动前被拒绝，或在产生第一行输出前退出。先看错误卡片，再看运行归档（如果有）。

### 为什么我改了配置，旧任务却没有变化？

Worker、Provider、Harness、运行指令、Skills 和 Runtime Bundle 身份在任务创建时冻结。验证新配置需要创建新任务。

### 任务一直排队，是不是提示词有问题？

通常不是。先检查预约时间、同一需求的前序任务、并发容量和运行时可用性。

### 运行结果正确，但没有 Merge Request？

创建需求时可能关闭了「创建合并请求」。这个选择之后不能修改，需要 MR 时请新建需求。

### 什么时候应该转给管理员？

错误涉及 Worker、Docker、Runtime Bundle、OIDC、加密密钥、平台重启，或所有任务同时失败时。附上任务编号、错误卡片和运行归档（如果有）。
