## 先判断问题在哪

先看任务当前的状态和页面提示，不要一开始就翻原始日志。大多数问题可以在任务详情页处理；涉及 Docker、Worker Runtime、平台重启、OIDC 或系统配置时，再交给管理员。

![先按症状分流：用户可以自助处理的任务问题，或需要管理员介入的平台问题](assets/diagrams/zh-CN/troubleshooting-split.svg)

| 你看到的情况 | 先做什么 |
|---|---|
| 任务显示「失败」 | 看任务详情页的「错误」卡片，再看下面的失败签名 |
| 任务一直是「待处理」或「已入队」 | 读队列提示，确认预约时间、前序任务和并发容量 |
| 提示词没有带上，或结果方向不对 | 检查任务提示词和运行指令模板，重点确认 `{{user_prompt}}` |
| 登录被跳回、页面返回 403、项目不在列表 | 先按本页的登录与权限说明检查；仍不行就联系管理员 |
| 容器缺失、Worker Runtime 不可用、平台重启后状态不一致 | 转到[《平台排障》](/guide/90-troubleshooting)，由管理员处理 |

## 任务失败时先看什么

打开任务详情页的「错误」卡片。卡片中的失败类型和错误信息比日志末尾更适合决定下一步；需要完整证据时，再按「事件流 → 原始日志 → 运行归档」的顺序查看。

| 错误信息特征 | 通常意味着什么 | 你的下一步 |
|---|---|---|
| `Task timed out after <n>s` | 本次任务用完了开始执行时冻结的超时上限 | 看「执行截止时间」；把工作拆小，或让管理员调整之后任务的超时策略 |
| `{"reason": "usage_limit_exceeded", ...}` | 创建或执行前触发了任务数、Token 或窗口配额 | 看错误里的 `scope`、`exceeded_items` 和重置时间；配额由管理员在「用量管理」调整 |
| `Code delivery was not confirmed...` | 分支推送被拒绝，或推送结果无法确认 | 把项目、分支和错误信息交给管理员或项目负责人检查机器人账号权限 |
| `protocol_error: ...` | Harness 的事件和进程结果对不上 | 先重试一次；再次出现时附上运行归档，让管理员查看平台排障章节 |
| `worker_runtime_unavailable`、`harness_cli_unavailable` | 任务冻结的 Worker Runtime 或 Harness 当前不可用 | 不要反复重试，联系管理员恢复并重新验证 Worker |
| `Worker failed to start: ...` | Worker 容器还没有正常启动 | 把任务编号和错误卡片交给管理员 |
| `Cancelled by user` | 这是主动取消，不是故障 | 不需要处理；仍要继续时追加任务或重新运行 |

失败任务可以打开「原始日志」查看容器输出；容器已经退出时，页面会使用执行期间保存的日志块。若任务在产生输出前就失败，日志为空是正常现象，错误卡片仍然保留原因。运行归档只在任务真正开始运行后才会有对应条目，过期后下载入口会停用。

## 任务没有开始

「待处理」和「已入队」都不代表任务失败。先读任务卡片上的队列文案，再按表格检查：

| 状态或提示 | 判断方式 |
|---|---|
| 待处理，预约时间在未来 | 等到预约时间，或使用「立即执行」跳过自己的预约等待 |
| 等待前序任务 | 同一需求一次只运行一个任务；前一个回合结束后才会轮到当前任务 |
| 排队等待 Worker | 其他需求占满并发容量；等待空闲槽位即可 |
| Worker Runtime 不可用 | 这是平台条件，不是提示词问题；联系管理员查看[《平台排障》](/guide/90-troubleshooting) |
| 所有任务都没有开始 | 让管理员检查调度器、Worker 和系统健康状态 |

预约时间只决定什么时候有资格进入队列，不能跳过同一需求的回合顺序。要改变当前任务的优先级、预约时间或执行方式，请在任务仍为「待处理」或「已入队」时使用编辑操作；任务开始后这些字段不会改变本次运行。

## 登录、项目和交付权限

| 症状 | 先检查 | 仍不行时 |
|---|---|---|
| 登录后立即回到登录页 | 会话是否过期；浏览器是否保存了站点 Cookie | 重新登录；反复发生时联系管理员检查登录配置 |
| 页面显示 `Admin access required` | 你是否在访问管理员页面 | 请管理员授予合适角色，或打开对应的共享页面权限 |
| 项目列表为空或找不到目标项目 | 当前登录账号是否能访问项目；平台管理员和本地登录账号使用的是机器人账号的可见范围 | 让管理员确认机器人账号能看到项目，并刷新项目列表 |
| 任务能创建但无法推送或创建 Merge Request | 机器人账号是否能向项目推送分支并创建 MR；受保护分支是否有额外规则 | 把任务错误和项目路径交给项目负责人或管理员处理 |
| 共享页面打不开 | Monitor、Schedule Overview 或 Analytics 是否对普通用户开放 | 请管理员在系统配置的「运行与共享」中开启对应页面 |

Codify 的登录权限和 GitLab 的项目权限是两套规则。能打开 Codify 页面，不代表任务就能推送代码；能看到项目，也不代表机器人账号拥有写权限。不要把访问令牌写进任务提示词或日志，敏感值应由管理员在配置页保存。

## 可以怎么处理

| 目标 | 建议操作 | 什么时候用 |
|---|---|---|
| 同一配置下再次运行 | 「重试」 | 任务因网络、配额恢复或其他瞬态条件失败；重试沿用源任务快照 |
| 在现有代码上继续 | 「追加任务」 | 需要补测试、修复一个具体问题或继续同一需求 |
| 清掉旧对话但保留代码 | 追加任务时选择「使用新会话执行」 | 旧会话方向不再适合，或需要更换 Harness |
| 更换项目、分支、合并目标或 Worker | 新建需求 | 这些设置在需求创建后冻结 |

追加任务时仍要重新写本回合的目标、范围和验证方式，不要只写「继续处理」。如果是提示词写错导致的结果偏离，优先追加一条更明确的任务；需求描述适合放跨回合成立的背景，不适合记录某一次修复的临时命令。

## 常见问题

### 为什么任务失败但没有原始日志？

任务可能在容器启动前就被拒绝，或在产生第一行输出前退出。先看错误卡片；容器已经运行过时，再看原始日志或运行归档。

### 为什么我改了配置，旧任务却没有变化？

任务创建时会冻结 Worker、Provider、Harness、运行指令和相关 Skill。配置修改只影响之后创建的任务；需要验证新配置时请创建新的任务。

### 任务一直排队，是不是提示词有问题？

通常不是。先看是预约时间、同一需求的前序任务，还是并发容量在等待。看到 Worker Runtime、调度器或容器相关提示时，请转给管理员。

### 运行结果正确，但没有 Merge Request？

创建需求时如果关闭了「创建合并请求」，任务只会推送工作分支，不会创建 MR。这个开关创建后不能修改；需要 MR 时请新建需求。

### 什么时候应该转给管理员？

当错误指向 Worker、Docker、Runtime Bundle、OIDC、加密密钥、平台重启或所有任务同时异常时，不要在同一任务上重复尝试。附上任务编号、错误卡片和运行归档（如果有），转到[《平台排障》](/guide/90-troubleshooting)。
